# ⚡️ Frontend & Advanced Rules (프론트엔드 및 심화 작업 규칙)

이 문서는 프론트엔드 개발, 아키텍처 규칙, 스타일링, 테스트 및 깃 커밋 등 심화된 개발 작업을 수행할 때 AI가 지켜야 할 가이드라인입니다.

## 1. 🏗️ Architecture & Imports (아키텍처 및 의존성)
- **FSD 의존성 규칙 준수**: 상위 계층은 하위 계층을 임포트할 수 있지만, 하위 계층이 상위 계층을 참조하는 '역방향 참조'나 '동일 슬라이스 간 교차 참조'는 엄격히 금지한다.
- **절대 경로 사용**: 별칭(Alias)이 설정된 경우 상대 경로(`../../`)보다 절대 경로(`@/...`)를 우선적으로 사용한다.

## 2. 🎨 UI/UX & Styling (스타일 및 접근성)
- **시맨틱 HTML**: `onClick` 이벤트를 `div`나 `span`에 직접 달지 않고, 용도에 맞는 시맨틱 태그(`<button>`, `<a>` 등)를 사용한다.
- **스타일링 원칙**: 인라인 스타일(`style={{...}}`) 사용을 지양하고, 프로젝트 내에 정해진 스타일링 방식(예: Tailwind, CSS Modules 등)을 철저히 따른다.
- **반응형(Responsive)**: 새로운 UI 컴포넌트를 작성할 때는 항상 모바일 환경을 같이 고려하여 반응형으로 작성한다.

## 3. 🛡️ Error Handling & Security (예외 처리 및 보안)
- **에러 삼키기 금지**: `try-catch` 블록에서 단순히 `console.error`나 `console.log`만 남기고 에러를 방치하는 것을 금지하며, 적절한 에러 핸들링 로직(사용자 피드백, 로깅 도구 연동 등)을 추가한다.
- **환경 변수 캡슐화**: 민감한 시크릿 키가 클라이언트 사이드 단에 노출되지 않도록 환경 변수(예: `NEXT_PUBLIC_` 유무)를 엄격히 구분해서 사용한다.

## 4. 🧪 Testing & Validation (테스트 및 검증)
- **테스트 코드 작성 원칙**: 새로운 비즈니스 로직이나 복잡한 유틸리티를 작성할 때는, 요청하지 않더라도 반드시 **단위 테스트(Unit Test, 예: Vitest)** 코드를 함께 제안한다.
- **엣지 케이스 고려**: 정상적인 동작 흐름(Happy Path)만 생각하지 말고, 항상 발생 가능한 예외 상황(Edge Cases)과 오류 상태를 미리 고려하여 방어적 프로그래밍(Defensive Programming)을 한다.

## 5. ⚡️ State Management & Performance (상태 관리 및 성능 최적화)
- **불변성 엄수**: 상태나 데이터를 변경할 때는 불변성(Immutability)을 훼손하는 직접적인 객체/배열 수정을 절대 금지한다.
- **렌더링 최적화**: (React/Next.js 환경인 경우) `useMemo`, `useCallback`을 무조건 남용하지 말고, 실제 렌더링 병목이 우려되는 경우에만 타당한 이유와 함께 메모이제이션을 적용한다.
- **비동기 데이터 관리**: 데이터 페칭 후에는 로딩 상태(Loading state)와 에러 상태(Error state) 처리를 누락하지 않는다.

## 6. 📝 Git & Version Control (기록 및 협업 가이드)

- **PR / 요약 규칙**: 작업이 끝난 후 내용을 요약할 때, "어떤 파일을 수정했다"의 나열이 아니라 **"어떤 목적/의도로 이 변경사항들이 필요했다"**를 중점적으로 브리핑한다.

## 7. 🌐 Web Vitals & Accessibility (성능 및 접근성)
- **이미지 및 에셋 최적화**: 정적 이미지는 반드시 Next.js의 `<Image />` 컴포넌트를 사용하여 `webp` 변환 및 지연 로딩(Lazy Loading)을 기본으로 적용한다.
- **웹 접근성(A11y)**: `<img>` 태그에는 의미 있는 `alt` 속성을 반드시 부여하고, 인터랙티브 요소는 키보드(`Tab` 키) 탐색이 가능하도록 `tabIndex`와 `aria-*` 속성을 적절히 활용한다.
